# 바투 AI 학습 — 리눅스(쓰레드리퍼) 인수인계 문서

> 이 문서는 리눅스 컴퓨터의 Claude Code에게 주는 인수인계입니다.
> 목표: `train_batoo.py`를 이 머신의 다코어 CPU로 장시간 돌려 `batoo_net.pt`를 키우는 것.

## 이게 뭔가

- **바투**: 2009년 서비스됐던 바둑 변형 게임(11×11, 중국룰 + 포인트지점 + 베이스돌 + 턴베팅)의 재현 프로젝트. 게임 본체는 맥에 있음 (`~/Desktop/야구/`).
- **train_batoo.py**: 미니 알파제로 — 작은 ResNet(정책+가치, 입력 7평면)이 MCTS 자가대국으로 스스로를 훈련. **이 파일 하나로 완결** (게임 규칙 내장, 외부 의존성은 torch뿐).
- **batoo_net.pt**: 학습 결과물이자 체크포인트. 이 파일만 맥으로 가져가면 게임 AI("🧠 신경망" 난이도)와 판세 기반 베팅에 자동 반영됨.

## 실행 (이 순서대로)

```bash
pip install torch --index-url https://download.pytorch.org/whl/cpu   # CPU 전용 휠 (작고 충분함)

# 1) 반드시 먼저: 몇 분짜리 동작 확인
python3 train_batoo.py --smoke --workers 2

# 2) 본 학습 (예: 3970X 32코어면 workers 24, 3990X 64코어면 40)
nohup python3 train_batoo.py --hours 24 --workers 24 --games-per-iter 48 > train.log 2>&1 &
tail -f train.log
```

- 같은 폴더에 기존 `batoo_net.pt`(구글 드라이브에서 받은 것)를 두면 **이어서 학습**.
- `--workers` = 병렬 자가대국 프로세스 수. 워커당 torch 스레드 2개로 제한돼 있음.
- 병렬 풀은 **spawn 방식 상시 풀**로 동작 (fork의 torch 뮤텍스 데드락 문제를 근본 회피).
  맥(macOS, spawn 기본)에서 `--workers 2` 스모크 실행 검증 완료 — 게이트 롤백 동작까지 확인됨.

## 🔁 재시작 (2026-07-08 백 편향 수정판) — 이걸로 새로 돌릴 것

이전 풀게임 모델(iter510)은 **백 정책이 무너져 백이 1선만 두는 버그**가 있었음.
원인: 덤(komi)을 무작위 고정 → 흑/백 승률 불균형 → 지는 쪽(백) 국면 정책이 평평해짐.
수정: `choose_komi`가 신경망 가치로 **공정 덤을 직접 계산**(흑/백 승률 50:50 유도) → 백 국면도 승부가 되어 정책 유지.

```bash
# 1) 이전 풀게임 모델은 버리고(백편향), 깨끗한 착수전용 iter739에서 새로 이식
mv batoo_net_full.pt batoo_net_full_OLD_iter510.pt   # 백업 (안 써도 됨)
# 2) 착수전용 최신 체크포인트(batoo_net.pt, iter739+)에서 이식 시작
nohup python3 train_batoo_full.py --hours 24 --workers 24 --games-per-iter 48 \
    --transplant batoo_net.pt > train_full.log 2>&1 &
tail -f train_full.log
```

**★ 이번엔 이 지표를 봐야 함**: 로그의 `흑 b·백 w`가 **12:12 근처로 균형** 잡히는지.
한쪽이 20:4처럼 계속 쏠리면 baiting 수정이 안 먹은 것 → 알려줄 것.
(이식 직후 정책손실 4.5→2.8 급락 = iter739 실력 승계 정상. 히든/스캔은 판당 1~4가 정상.)

## 🆕 2단계: 풀게임 학습 (train_batoo_full.py) — 베팅·히든·스캔 통합

착수 전용 모델이 UCT를 넘은 뒤(2026-07-08, iter739 승률 62% 달성) 시작하는 확장 학습.
행동 364개(일반착수/히든착수/스캔/쉼), 불완전정보 determinization MCTS, 11평면 입력.

```bash
python3 train_batoo_full.py --smoke --workers 2                        # 동작 확인
nohup python3 train_batoo_full.py --hours 24 --workers 24 --games-per-iter 48 \
    --transplant batoo_net.pt > train_full.log 2>&1 &
```

- `--transplant batoo_net.pt`: **기존 착수 모델의 몸통을 이식**해서 시작 (0에서 다시 안 배움).
  출력은 `batoo_net_full.pt` — 기존 파일과 별개. 기존 착수 학습(train_batoo.py)은 중단해도 됨.
- 로그에 `히든 h·스캔 s` 항목 추가 — 판당 히든 ≤2(양쪽 합), 스캔 ≤6. **둘 다 0이 지속되면 안 배우는 것**이니 보고할 것.
- 추가 간이 규칙: 진실상 패(동형반복)인데 보이는 판에선 합법인 수 → 상대 히든 전부 공개 + 차례 소모 (극히 드묾).
- 완성된 batoo_net_full.pt를 맥에 가져가면 서버 연동은 맥 쪽에서 처리 (구조가 달라 기존 신경망 난이도와 별도 연동 필요).

## 로그 읽는 법 (건강 지표)

```
[iter N] 대국 48판(XXXs, 흑 a·백 b·무 c) | 버퍼 B | 정책손실 P 가치손실 V | ...
```

| 지표 | 건강 | 이상 |
|---|---|---|
| 판당 평균 수 = (버퍼 증가량 ÷ 판수) | 90~140 | 60 근처(조기 쌍쉼 꼼수) 또는 12~34(붕괴) |
| 흑·백 균형 | 12±5 / 24판 | 한쪽 20+ 지속 |
| 무승부 | 0~4 | 10+ 지속 |
| 정책손실 | 4.8(균등)에서 서서히 하강, 3점대가 목표 | 안 내려감 |
| 가치손실 | 0.2~0.5 등락하며 완만 하강 | — |

## ⚠️ 2026-07-07 사건: 자기 과신 소용돌이 (v5에서 수정됨)

iter 35까지 달린 모델이 iter 7보다 약해지고, 자기 대국 승패 예측이 28%(역상관)까지 떨어진 사건.
원인: 가치망이 작은 버퍼에 과적합 → 정책이 잘못된 믿음을 따라 지는 라인을 파고드는 되먹임.
(정상 국면 판단은 73%로 멀쩡했음 — 자기가 만든 판에서만 헛발. 병렬 코드 문제 아님, 리눅스 수정 문제도 아님.)

v5 수정: ①학습률 1e-3→3e-4 ②훈련 스텝 절반 ③**게이트** — 5 iter마다 신모델 vs 최고기록 10판 스파링,
승률 45% 미만이면 자동 롤백 (로그에 `[게이트] ... 채택/롤백` 줄이 찍힘. 롤백이 연달아 5번+ 나오면 얘기해줄 것).
이 사건의 오염 모델은 폐기하고 **처음부터 새로 시작**할 것 (기존 batoo_net.pt 삭제 후 실행).

## 이 프로젝트에서 이미 겪고 고친 것들 (재발 시 참고)

1. **조기 쌍쉼 붕괴**: 동점=백승 규칙 때문에 백이 일찍 쉬는 걸 배워 판이 12수 만에 끝났음.
   → `legal_mask`에서 쉼을 "둘 곳 없거나 60수 이후"로 제한해서 해결. 판 길이가 60대에 몰리면 이 꼼수의 재발이니 쉼 조건을 강화할 것.
2. **백 편향**: 덤 없이 학습하면 백이 20/24씩 이기는 피드백 고리.
   → 매판 무작위 정수 덤(0~7) + 덤 입력 평면(7번째)으로 해결. 지금은 덤 조건부 가치를 학습함.
3. **규칙 3벌 동기화**: 게임 규칙을 바꾸면 맥의 `batoo/index.html`(JS 로컬), `server.py`(파이썬 서버), `train_batoo.py`(학습) 세 곳을 같이 바꿔야 함. 여기서는 train_batoo.py만 만지고, 규칙 자체는 바꾸지 말 것 (신경망 구조나 규칙이 바뀌면 기존 체크포인트가 무효가 됨).
